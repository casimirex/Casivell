Walkthrough README Roadmap

Start here

Casivell is a payroll, tax and household simulator for Germany. It runs entirely on your device, uses exact integer arithmetic, and traces every figure back to the statute that produced it.

Correct

Every statutory figure cites its provision and primary source. Calculations use integer cents and rates in parts-per-million.

Local-first

No network code path. In the browser it is a WebAssembly module; on the command line it is a single binary.

Explainable

Every result names the rule behind it. A number you cannot check is a number asking for trust it has not earned.

This book takes you from the first payslip to the engineering that keeps the numbers honest. No Rust knowledge is required for the first half; the second half is for contributors and auditors who want to understand how the engine is built and verified.

Part I — The beginner's tour

This part is for anyone who wants to use Casivell. It assumes you know what a payslip looks like and nothing else.

1 · What Casivell computes

Casivell answers the questions German households actually face: what is my net pay?, which tax class should we choose?, what does part-time cost over a lifetime?, and can we afford to buy a home?

It does this by running German statute through a precise simulation engine. The engine handles:

  • Payroll withholding — monthly or yearly net pay from gross, using the BMF Programmablaufplan for Lohnsteuer and the current social-insurance rates.
  • Annual assessment — the § 2 EStG path that produces a Steuerbescheid, with Werbungskosten, Sonderausgaben and außergewöhnliche Belastungen.
  • Tax-class comparison — IV/IV, III/V and IV+Faktor for couples, showing that the annual tax is the same and only the timing differs.
  • Capital income — § 32d flat tax and the Abs. 6 election.
  • Household projection — decades of payroll, savings, life events and pension accrual, month by month.
  • Property purchase — Kaufnebenkosten, Grunderwerbsteuer and an annuity mortgage.

Two front ends call the same engine: a React + Vite browser app in web-react/ and a command-line tool in crates/casivell-cli. Both produce the same figures to the cent.

2 · The five concepts you need

2.1 · Money is integer cents

Inside Casivell there are no floating-point euro amounts. A euro is 100 cents, stored as an integer. This eliminates the rounding drift that makes a long projection subtly wrong. The web UI still shows 2.871,09 €, but the conversion to text happens at the boundary, never in the calculation.

Why this matters. A cent of drift every month becomes 4,80 € after forty years. More importantly, the German statute itself rounds at named points; doing that with floats makes it possible to round the wrong thing.

2.2 · Rates are parts-per-million

A rate like 9,3 % is stored as 93 000 ppm. Multiplying a cent amount by a ppm rate and dividing by 1 000 000 is exact integer arithmetic, with a named rounding rule at the end.

2.3 · Tax classes are about timing, not total tax

Germany has six Lohnsteuerklassen. For a single person the class is fixed. For married couples there are three arrangements — IV/IV, III/V and IV with Faktor — and the annual income tax is the same under all of them. The choice changes how much is withheld each month and whether you get a refund or owe money at assessment.

2.4 · Social insurance has four branches

A German payslip deducts four employee shares:

  • Rentenversicherung — pension.
  • Arbeitslosenversicherung — unemployment.
  • Krankenversicherung — health, including the fund-specific Zusatzbeitrag.
  • Pflegeversicherung — care, with a childless surcharge and per-child reductions.

Each has its own contribution ceiling, rate and incidence rules.

2.5 · Enacted law ends; assumptions begin

Casivell contains the statutory parameters for 2025 and 2026. Past that, the engine projects from explicit assumptions — inflation, wage growth, investment return — and labels the result PROJECTED. It never silently pretends a future year is already law.

3 · The browser interface

Open web-react/dist/index.html after a build, or run npm run dev. The page has three tabs: a payslip, a tax-class comparison and a projection. There is no submit button and no network request; results update as you type.

3.1 · The three forms

3.2 · UI/UX details that matter

  • Hero cards surface the headline number immediately.
  • Animated numbers interpolate when inputs change, making the connection visible.
  • Input adornments (€, %) remove ambiguity about units.
  • Theme and language selectors persist your choice in localStorage.
  • Reduced-motion media query disables animations for users who prefer it.

All of this is built with CSS custom properties and a few tiny hooks — no UI library, no chart dependency.

4 · German and English

The page can be switched between German and English via the header, or by adding ?lang=de or ?lang=en to the URL. German is the fallback.

Notice that the statutory terms stay German in both languages. Lohnsteuer, Sozialabgaben and Nettolohn are the words printed on a German payslip. Translating them would make the result harder to check against the document it came from. The chrome and explanations change; the figure names do not.

5 · Explainability

Selecting a deduction row opens the provision behind it. For Lohnsteuer this is the full § 39b chain in the BMF Programmablaufplan's own variable names.

The same chain appears in the CLI output, so the browser and the terminal agree line for line. This is not a nicety; it is the project's definition of correctness. If two paths through different statutes do not agree, one of them is wrong.

Part II — Using it well

This part is for users who want the command line, projections and saved scenarios. It assumes you have built the workspace once.

The CLI is the casivell command, produced by cargo build -p casivell-cli. It exposes every form the engine has. The quickest way to try it is:

$ cargo run -p casivell-cli -- --gross 4500 --class 1

7 · Household projections

A projection answers the lifetime questions. It runs the same payroll code month by month for decades, applies statutory parameters for each year, and records wealth, pension accrual and life events.

7.2 · Life events

Options include --part-time, --break, --raise, --child-born, and --parental-leave. Five years at 60 % pay pushes this household into deficit for six years and lowers pension points permanently, because Entgeltpunkte are a ratio to the national average wage. That is the Teilzeitfalle — the part-time trap — and showing it is the point.

8 · Saving and comparing scenarios

A saved scenario records the invocation and the fingerprint of the statutory data it was computed against. This lets you replay it later and know whether the law has changed underneath.

$ cat rent.casivell
# Casivell scenario
# Replay with: casivell replay <this file>. Editable by hand.
schema = 1

[invocation]
form = project
arg = --gross
arg = 6000
arg = --class
arg = 1
arg = --expenses
arg = 1500
arg = --return
arg = 5,0
arg = --years
arg = 25

[law]
year = 2026
fingerprint = e177cfbaa6bb7121

Replaying checks the fingerprint first:

$ cargo run -p casivell-cli -- replay rent.casivell
  … projection output …
  Replayed against unchanged 2026 law (e177cfbaa6bb7121).

If the data has moved, the warning comes first, because a caveat under several screens of numbers is one nobody reads. Two scenarios can also be compared directly:

$ cargo run -p casivell-cli -- compare rent.casivell buy.casivell

Part III — Under the hood

This part is for engineers, auditors and contributors. It explains how the engine is layered, how its correctness is defended, and where its limits are.

9 · Architecture and trust boundaries

9.1 · Workspace layout

crates/
├── casivell-core/      Money (integer cents), Rate (integer ppm), named rounding
├── casivell-lawdata/   Year-keyed statutory tables, each figure cited
├── casivell-tax/       § 32a EStG tariff, Solidaritätszuschlag, church tax
├── casivell-income/    § 2 EStG: gross → taxable income, the assessment, § 32d capital
├── casivell-social/    Social insurance contributions, pension entitlement
├── casivell-benefits/  Elterngeld (BEEG)
├── casivell-property/  Grunderwerbsteuer, Kaufnebenkosten, annuity mortgage
├── casivell-payroll/   Lohnsteuer (BMF Programmablaufplan), gross-to-net
├── casivell-projection/ Statutory parameters past the last enacted year
├── casivell-sim/       Month-by-month household projection, streaming
├── casivell-cli/       The casivell command
└── casivell-wasm/      A dependency-free C ABI, for the browser build in web/

The dependency direction is the design:

  • casivell-core knows nothing of German law.
  • casivell-lawdata holds law but performs no calculation.
  • Calculation crates hold no statutory constants.

9.2 · Why a hand-written C ABI for the browser

The engine compiles to WebAssembly. Instead of using wasm-bindgen, the project exposes a tiny C ABI manually. This keeps the workspace free of third-party dependencies: every line that computes a German tax figure is in the repository and reviewable, and the build has no supply chain.

The ABI is intentionally narrow:

  1. Call casivell_payslip(...) with the inputs. It returns 0 on success or a negative error code.
  2. Call casivell_result(field) to read each figure out, in cents as i64.

Because values are i64, JavaScript sees them as BigInt. The web app converts to a number for display, but the arithmetic stays in the engine.

9.3 · Local-first as architecture

Privacy is defended by verifiable measures, not proofs. The engine is #![no_std], which has no way to open a socket. The browser build can use a CSP with connect-src 'none'. The WASM is reproducible from source. The user can open the developer tools and confirm no network request is made.

10 · How the numbers are checked

10.1 · The BMF Prüftabellen

Lohnsteuer is checked against all 516 official values of the BMF Programmablaufplan's Prüftabellen — the reference tables German payroll products are validated against. These cover 43 salary levels across all six tax classes in two variants. Casivell matches every one exactly.

10.2 · Two statutes agreeing

Withholding under § 39b is designed to be right for a flat year. The annual assessment under § 2 should therefore return almost nothing on a flat year. The two paths share only the tariff; one runs the BMF Programmablaufplan with its simplified Vorsorgepauschale, the other § 2 EStG with the real § 10 deduction. They land within 96–332 cents of each other across a sixfold salary range. Nothing makes them agree except both being right.

10.3 · Derived, not invented

Projected tariff coefficients are derived from the enacted Eckwerte. The derivation reproduces all eight published coefficients for both 2025 and 2026 exactly. This is what makes a projected tariff credible rather than fabricated.

10.4 · Fingerprints and the Datenstand

Every year's statutory data has a stable FNV-1a fingerprint over the figures themselves. A saved scenario records this fingerprint, so a replay can warn if the law has moved. The browser footer shows the Datenstand — the statutory data version — so a cached build names the law it rests on.

10.5 · External references

An independent decimal implementation of § 32a in docs/reference/ cross-checks the engine's integer algebra across the whole curve. The DRV "Standardrentner" figure — 45 Entgeltpunkte at the 1 July 2026 Rentenwert giving 1 913,40 € — also matches.

11 · Engineering discipline

The engine follows the JPL "Power of Ten" coding standard, adapted to Rust.

ConstraintMechanism
No heap allocation in the engine#![no_std] — no allocator
No unsafe code#![forbid(unsafe_code)]
No panics in library codeunwrap, expect, panic, indexing all denied
No unchecked arithmeticclippy::arithmetic_side_effects denied
No floating pointclippy::float_arithmetic denied
Bounded functions60-line limit, complexity limit
Zero warningsclippy::pedantic with -D warnings in CI

Money and Rate deliberately do not implement Add/Sub/Mul. Every operation is a named method returning Result. Call sites are more verbose, and that is the point: the surest way to have every return value checked is to leave no unchecked alternative.

11.1 · What the CI enforces

$ cargo test --workspace
$ cargo clippy --workspace --all-targets -- -D warnings
$ cargo build --workspace --target wasm32-unknown-unknown --release
$ python3 scripts/check_no_statutory_literals.py
$ python3 docs/reference/generate_tariff_reference.py

Each step is reproducible on a laptop. A CI that cannot be run locally teaches people to push and pray.

12 · What it will not do

The full account is in docs/LIMITATIONS.md. The most important limits are:

  1. A second earner is not modelled. If both spouses work, the annual assessment is refused rather than computed on half a household.
  2. Only employment and capital income. Business, self-employment, rental, agriculture and pensions in payment are absent.
  3. Nothing has been reconciled against a real Steuerbescheid. The internal evidence is strong; it is not the same thing.
  4. Minijob and Übergangsbereich contributions are wrong. The Midijob formula is not implemented.
  5. Weekly and daily pay periods are refused. Their scaling factors do not terminate in decimal.
Not tax advice. Casivell is an information and simulation tool, not advice within the meaning of Steuerberatungsgesetz §§ 1–4. Where a real filing or decision is at stake, a Steuerberater is the answer.

13 · From novice to professional

If you are new to the codebase, start in this order:

  1. Run cargo run -p casivell-cli -- --help and try a payslip. Compare it with a real payslip if you can.
  2. Open web-react/dist/index.html and click through the three forms. Open the explanation panel and read the § 39b chain.
  3. Read crates/casivell-core/src/lib.rs to see how Money and Rate work. Notice they are integers, and operations return Result.
  4. Read crates/casivell-lawdata/src/lib.rs to see the Provenance structure: provision, URL, verification date and status.
  5. Read docs/ROADMAP_ERRATA.md to see what was wrong in the previous version and how the current checks prevent it.
  6. Read docs/CODING_STANDARD.md for the full rules and their enforcement mechanisms.
  7. Try adding a new year. The first failure will come from a test that checks the tariff zones join continuously — this is the design catching a mistranscription before a user sees it.

The project's quality is not in any single clever algorithm. It is in the accumulation of small guards: integer money, cited data, named operations, no panics, no network, reproducible tests, and a LIMITATIONS file that is read before it is hidden. That is what makes a tax calculator worth trusting.
